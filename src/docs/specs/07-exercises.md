# 07 — Exercises

## Principle

Generate with code where possible, with the LLM only where creativity is needed (sentences).
Grade deterministically wherever possible. Store generated exercises; never send `answer` to the client.

## Types

| Type | Generated by | Graded by | Card type trained |
|---|---|---|---|
| `HANZI_TO_MEANING` | code | code | RECOGNITION |
| `TONE` | code | code | TONE |
| `MEANING_TO_HANZI` | code | Hanzi Writer quiz result | WRITING |
| `FILL_BLANK` | LLM | code | RECOGNITION |
| `WORD_ORDER` | LLM | code | RECOGNITION |
| `TRANSLATION` | LLM | LLM | WRITING |

## JSON shapes (`prompt` / `answer` / client `response`)

### HANZI_TO_MEANING
```jsonc
prompt:   { "hanzi": "朋友", "options": ["friend", "teacher", "older brother", "classmate"] }
answer:   { "correct": "friend" }
response: { "selected": "friend" }
```
The correct option is `word.meaningEn` verbatim, so the answer can also be derived from the word alone (spec 09).
Distractors: 3 meanings of other words, preferring the same lesson and the same part of speech;
fall back to any confirmed word, then to CEDICT words of the same length. Shuffle options.
Exclude distractors that are equal to the correct meaning or share a meaning segment with it
(split on `;` and `,`, trimmed, case-insensitive), e.g. 学 vs 学习 "to learn". All option texts are distinct.

### TONE
```jsonc
prompt:   { "hanzi": "朋友", "syllables": ["peng", "you"] }
answer:   { "tones": [2, 5] }
response: { "tones": [2, 5] }
```
UI: one row of buttons 1–4 + "neutral" per syllable; plays nothing in v1 (audio is out of scope).
Expected tones are the dictionary (citation) tones from `word.pinyin_numbered`; sandhi is not asked.
Syllables come from `pinyin_numbered`; erhua `r5` and Latin tokens are not asked.
`score` = share of correct syllables; `correct` only if all correct.

### MEANING_TO_HANZI
```jsonc
prompt:   { "hanzi": "朋友", "meaningEn": "friend", "meaningDe": "Freund", "pinyin": "péngyou", "characterCount": 2 }
answer:   { "hanzi": "朋友" }
response: { "hanzi": "朋友", "strokeMistakes": [0, 2], "hintsUsed": 1, "skipped": false }
```
Grading:
- `skipped: true` (Skip button) → `correct = false`, `score = 0`.
- A character **fails** if it has > 3 mistakes (the outline was shown, `showHintAfterMisses: 3`).
  Characters without stroke data are self-assessed and reported as `0` (correct) or `4` (wrong) mistakes.
- `score` = share of characters that did not fail; `correct` = `score == 1`.
The prompt carries `hanzi` because Hanzi Writer needs the target characters; the client does not display them
until finished. Accepting that the answer is technically in the client is fine for a personal learning app.
Only words made entirely of Chinese characters are asked (no stroke data for Latin letters, e.g. `AA制`).
The prompt shows the meanings and pinyin, so editing any of them makes a stored exercise stale (see "Practice session").

### FILL_BLANK
```jsonc
prompt:   { "sentence": "我和我的___去学校。", "translationEn": "I go to school with my friend.",
            "options": ["朋友", "老师", "学生", "妈妈"] }
answer:   { "correct": "朋友", "fullSentence": "我和我的朋友去学校。" }
response: { "selected": "朋友" }
```

### WORD_ORDER
```jsonc
prompt:   { "tokens": ["学校", "我", "去", "明天"], "translationEn": "I will go to school tomorrow." }
answer:   { "accepted": [["我", "明天", "去", "学校"], ["明天", "我", "去", "学校"]] }
response: { "order": ["我", "明天", "去", "学校"] }
```
The LLM must list every grammatically acceptable order (usually 1–2). Tokens shuffled server-side;
the shuffled order must not equal any accepted order.

### TRANSLATION
```jsonc
prompt:   { "source": "Ich lerne mit meinem Freund Chinesisch.", "sourceLang": "de",
            "hintWords": ["朋友", "学习"] }
answer:   { "reference": "我和我的朋友学习中文。" }
response: { "text": "我跟朋友学中文。" }
```
Graded via `TranslationGrader` (LLM) → `{correct, score 0..1, feedback (English, ≤ 2 sentences), corrected}`.
`sourceLang`: alternate between `de` and `en`.

## LLM generation

```java
public interface ExerciseGenerator {
    List<GeneratedExercise> generate(ExerciseType type, List<WordDto> targetWords,
                                     Set<String> allowedWords, int count);
}
```

- **Target words**: the lesson's words, spread evenly; words with the fewest stored exercises of the requested
  type first (count via `exercise_word`).
- **Allowed words**: all words in the vocabulary **except** those that appear only in lessons of the same textbook
  with a higher `lesson_no`, plus a fixed whitelist of basic function words
  (`的 了 是 不 很 吗 呢 也 都 和 在 我 你 他 她 们 这 那 个 有`) and numerals (`一 二 三 四 五 六 七 八 九 十 两 百`).
- Prompt files in `src/main/resources/prompts/`: `gen-fill-blank.st`, `gen-word-order.st`, `gen-translation.st`,
  `grade-translation.st`.
- Prompts state: simplified characters only; natural, short sentences (≤ 15 characters for beginners);
  use only allowed words (list passed in prompt); each sentence must contain at least one target word;
  for `FILL_BLANK`, distractor options must not fit the sentence grammatically or semantically.

### Allowed-character validation (mandatory)

LLMs ignore vocabulary constraints, so check in code:
- Build the set of characters from all allowed words.
- Every CJK character in a generated sentence must be in that set (punctuation ignored).
- Exercises failing the check are discarded; regenerate the missing count up to 2 more times;
  report `rejected` count in the generation job.

Also discard: duplicate sentences (vs. stored exercises for this lesson), `FILL_BLANK` whose correct
option is not in the options or whose blank count ≠ 1, `WORD_ORDER` whose tokens ≠ any accepted order's multiset.

## Practice session

`POST /api/practice/sessions {lessonId, types?, size?}`:
- Code-generated exercises are created on the fly if fewer than needed exist.
- LLM types are only taken from stored exercises (generation is a separate, explicit action).
- Mix types; never two exercises for the same word back-to-back (unless only one word is left).
- Each word/type pair appears at most once per session; a lesson with fewer pairs than `size` gives a shorter
  session. `size` defaults to `hanzi.exercises.default-session-size` (15); `types` defaults to the types the
  player supports (M6: `HANZI_TO_MEANING`, `TONE`, `MEANING_TO_HANZI`).
- A stored code-generated exercise whose answer or prompt no longer matches its word (meaning edited) is deleted
  and regenerated.
- Answers in free practice are graded but not stored.

## Suggested rating (shared with spec 09)

| Outcome | Rating |
|---|---|
| wrong (`score < 0.5`) | 1 Again |
| partially right, or handwriting with > 2 total stroke mistakes, or hint used | 2 Hard |
| correct | 3 Good |
| correct, no mistakes, `durationMs` < 5 s (8 s for writing) | 4 Easy |

In free practice (`/practice`), ratings are **not** applied to review cards. Only `/review` updates FSRS.
